## 二、本轮发现并修复的缺陷（3 个真实缺陷）

| # | 严重 | 模块 | 缺陷 | 修复 |
|---|---|---|---|---|
| 1 | **高** | 模型/附件 | `Attachment` 模型缺 `biz_type` 字段；upload 接口传 `biz_type` 关键字导致 `TypeError: unexpected keyword` → 500 | `backend/app/models/ops.py` 加 `biz_type: Optional[str]` |
| 2 | **中** | 测试 | 「未开考」用例 `class_ids=[], student_ids=[]` → 学生没被下发，取卷被「任务未下发」拦下，**不是「未开考」拦截**，断言语义错 | 加 `student_ids=[stu731.user.id]` 让用例真正覆盖未开考拦截路径 |
| 3 | **中** | 测试 | `/attachment` 应为 `/attachments`（带 s）；`/grading/tasks/{id}/grade` 应为 `/grading/submissions/{id}/grade`；`/task/tasks/{id}/score` 应为 `/task/my/scores` | 修测试期望（产品路径无 bug） |

## 三、覆盖说明与未覆盖风险

### 3.1 已覆盖的关键路径

- **端到端业务流**：教师出题 → 组卷 → 发布作业 → 学生作答 → 提交 → 教师批改 → 学生查分
- **越权矩阵**：管理端专属接口对教师/学生全部 403；教师/学生跨班 403；学生只能看自己
- **AI 链路**：7 类 Agent 全部覆盖（含 LLM 未配置时的规则引擎降级）
- **数据完整性**：多选题答案、SQLite Text 列、JSON 序列化、ChromaDB where 单操作符
- **令牌安全**：刷新、登出吊销、异地告警、心跳

### 3.2 未覆盖的边界（已知风险）

| 风险 | 原因 | 建议补测 |
|---|---|---|
| 前端 UI 渲染层 | 端到端走 HTTP，未跑 Playwright | 接入 `workbuddy-browser-use` 做视觉冒烟 |
| 高并发抢答 | 单进程 SQLite 无并发 | 切 PostgreSQL 后加并发用例 |
| 大量数据下的报表性能 | 干净数据卷 | 加 stress 模式（10k 题目） |
| 移动端适配 | 未测 | 用 browser-use 跑响应式用例 |
| LLM 真实输出 | 未配 `LLM_API_KEY` | 配后补一组真实模型用例 |

### 3.3 已知产品限制（非缺陷）

- `LLM_API_KEY` 未配置时所有 AI Agent 走规则引擎降级，主观题进人工批改队列
- 令牌吊销名单在进程内存，多副本部署需换 Redis
- `alembic` 未初始化，依赖 `Base.metadata.create_all`（生产环境会卡表结构变更）
