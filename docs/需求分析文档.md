> 系统代号：edu-ai-platform（原"九年义务教育 AI 学习管理系统"）
> 版本基线：2.0.4 ｜ 文档状态：基于代码实测复盘（非预测）
> 适用范围：开发、评审、产品对齐参考

## 1. 文档说明与范围

本文档基于 `edu-ai-platform` 仓库（后端 `backend/app`、前端 `frontend/src`、测试 `tests/`、工具 `tools/`）的实际代码结构编写，覆盖已落地功能与可验证的设计意图。所有功能点均可在源码中定位；未实现的规划项会明确标注为"待建"。

文档目标：

1. 明确系统定位、目标用户与可达成的业务/技术目标；
2. 梳理贯穿"教—学—练—考—评—改"的核心业务流程；
3. 以清单形式给出模块化功能点并标注优先级（P0 必备 / P1 重要 / P2 增强）；
4. 给出非功能性需求与一致性约束，为架构与排期提供依据。

## 2. 系统概述

### 2.1 系统定位

面向中国九年义务教育阶段（小学 1–6 年级 / 初中 7–9 年级）的轻量化校内学习管理系统。以"教学全流程数字化 + AI 辅助"为核心，覆盖出题、组卷、发布、作答、批改、学情分析、个性化复习的完整闭环，并内置 8 个 AI Agent 提供出题、组卷、批改、答疑、规划、笔记、教案等智能能力。

### 2.2 目标用户与角色

| 角色 | 代码标识 | 核心职责 |
|------|----------|----------|
| 系统管理员 | `sys_admin` | 用户/角色/权限、AI 与系统配置、注册审批、日志、定时任务、系统全景报表 |
| 年级管理员 | `grade_admin` | 年级/学科/班级等教育资源的写权限，年级/学科横向对比（只读） |
| 教师 | `teacher` | 出题组卷、作业考试发布、智能批改、班级学情分析、教案编写 |
| 学生 | `student` | 作答、练习、错题本、笔记、智能复习、成绩中心、学习路径 |
| 访客/游客 | `guest` | 受限公共能力（如验证码、注册入口） |

> 鉴权依赖注入器见 `backend/app/api/deps.py`：`get_current_admin` / `get_current_manager` / `get_current_teacher` / `get_current_student` / `get_current_student_self`（仅学生可写自身数据，防代建）。

### 2.3 设计原则

- **全流程闭环**：教学业务从"资源建设"到"学情反馈"形成可追踪的数据链。
- **AI 降级保障**：未配置大模型 API Key 时，所有 Agent 自动切换为规则引擎，功能不中断（`llm_enabled=false`）。
- **轻量部署**：单体前后端一体 Docker 镜像，2 核 4G 即可支撑约 500 人在线。
- **四层一致性**：本地代码 / 远程仓库 / Docker 镜像 / 服务器部署必须同源（见架构文档 §10）。

## 3. 系统目标

### 3.1 业务目标

- **B1 资源数字化**：构建 1–9 年级学科体系、多级知识点树、班级与题库/试卷资源库。
- **B2 教学自动化**：教师可快速出题/组卷/发布，系统自动批改客观题、辅助批改主观题。
- **B3 学情可视化**：为教师/管理员提供班级横向对比与系统全景，为学生提供个人学习总览。
- **B4 个性化学习**：基于作答数据生成错题本、艾宾浩斯复习计划、学习路径与薄弱点地图。
- **B5 AI 提效**：8 个 Agent 覆盖出题、组卷、批改、答疑、规划、笔记、教案，降低重复性劳动。

### 3.2 技术目标

- **T1 高内聚低耦合**：路由（api/v1）→ 服务（services）→ 模型（models）分层清晰。
- **T2 可移植数据层**：SQLite（WAL）默认，可平滑切换 PostgreSQL（连接池已抽象）。
- **T3 可观测**：登录/操作/错误三类日志 + 审计中间件 + Agent 调用日志（daemon 线程落库）。
- **T4 安全可控**：PBKDF2 密码哈希、JWT 双令牌、RBAC 三级权限（菜单/操作/数据）、令牌吊销。
- **T5 可发布可追溯**：镜像烧录 `BUILD_INFO`/`GIT_COMMIT`，四层指纹一致性校验。

## 4. 核心业务流程

### 4.1 教学主链路（教师侧 → 学生侧）

```
[教师] 建知识点 → 建题(手动/AI) → 组卷(手动/AI) → 布置任务(homework/exam/practice, 可定时)
   │                                                                                    │
   ▼                                                                                    ▼
[学生] 取卷(无答案) → 作答(heartbeat 防切屏) → 提交 → 系统自动判分 + 主观题 LLM 批改
                                                                          │
                                                                          ▼
[教师] 批改中心: 查看待批改 → 采纳/修正 → 发布成绩 → 学情分析
                                                                          │
                                                                          ▼
[学生] 成绩中心 → 错题本 → 智能复习(艾宾浩斯) → 笔记/学习路径 → 掌握度地图
```

关键代码链：
- 提交：`task.py:/tasks/{id}/submit` → `grading_service.save_answers`（先 commit 释放写锁再调 LLM）→ `finalize_submission`（算分/排名/错题/掌握度）。
- 批改：`grading.py:/submissions/{id}/grade`、`/batch/grade`、`/publish`；主观题由 `GradingAgent` 并发批改。
- 复习：`StudyPlannerAgent` 生成 `ReviewPlan`；`task_jobs.push_review_reminders` 定时推送。

### 4.2 注册审批流程

学生/教师注册 → `Registration` 待审批（`auth_service.register_user` 通知管理员）→ 管理员 `audit_registration` 通过/驳回 → 账号激活可登录。默认管理员 `admin` 由种子脚本创建。

### 4.3 AI 异步长任务流程（教案/智能任务）

```
前端提交 → /lesson/ai/generate 或 /agent/jobs[POST]
   → 后台线程 _run_job 执行（AgentJob 记录状态）
   → 前端轮询 /jobs/{id}（教案 2s 轮询，含 resumeJobId 断点恢复）
   → 完成返回结构化结果 → 用户预览 → POST /jobs/{id}/save 落库
```

> 生成与保存分离：AI 生成结果不立即落库，用户确认后才保存，避免脏数据。

### 4.4 知识点 RAG 检索流程

`knowledge.py:/knowledge/search` → `rag.py:search()`（Chroma 向量优先 + SQL 降级）→ 返回知识点片段及引用来源；首次检索触发后台预热（约 79MB 模型下载）。

## 5. 功能需求清单

优先级：**P0 = 必备（无则系统不可用）**；**P1 = 重要（核心体验）**；**P2 = 增强（锦上添花）**。

### 5.1 系统基础（system / auth / logs / jobs / attachments）

| 功能 | 路由/模块 | 优先级 | 说明 |
|------|-----------|--------|------|
| 账号注册 + 审批 | `/auth/register`、`/auth/registrations[/audit]` | P0 | 注册后进入审批流 |
| 登录/刷新/登出 | `/auth/login`、`/refresh`、`/logout` | P0 | JWT 双令牌，登出写入吊销名单 |
| 图形验证码 | `/auth/captcha` | P0 | Noto CJK 字体，防爆破 |
| 改密/重置 | `/auth/password`、`/reset-password` | P0 | 管理员重置用 `new_password` |
| RBAC 三级权限 | `system.py:/roles`、`/permissions` | P0 | 菜单/操作/数据三级，约 60 权限点 |
| 用户管理 | `system.py:/users` | P0 | 增删改、重置密码、启用禁用 |
| 通知管理 | `system.py:/notifications` | P1 | 站内通知 |
| AI 配置 | `system.py:/ai-config[/test]` | P1 | 脱敏展示、掩码跳过、实时连通测试 |

## 6. 非功能性需求

| 类别 | 需求 | 当前实现 / 约束 |
|------|------|----------------|
| 性能 | 2 核 4G 支撑 ~500 并发 | SQLite WAL + `busy_timeout` + 写锁释放策略 |
| 可用性 | LLM 不可用时功能不中断 | 规则引擎降级（`_rule_*` / 本地判分） |
| 安全 | 密码/令牌/JWT | PBKDF2-SHA256、JWT 双令牌、令牌进程内吊销名单 |
| 安全 | 越权防护 | `DataScope` 显式列表隔离；作答校验下发关系 |
| 数据 | 多副本一致性 | SQLite 单写者；令牌吊销为进程内（多副本需换 Redis，已注释标注） |
| 部署 | 一键部署 | Docker 多阶段 + Compose + Nginx 一体镜像 |
| 可观测 | 日志/审计 | 三类日志 + `AuditMiddleware` + `AgentCallLog` |
| 一致性 | 四层同源 | `verify_consistency.py` 校验本地/远程/镜像/服务器指纹 |
| 时区 | 服务端时间契约 | `/health` 返回 `server_time`，测试统一 `server_now()` |

## 7. 功能优先级汇总（排期参考）

- **P0（必交付，当前均已实现）**：注册审批、登录鉴权、RBAC、三类日志、年级/学科、知识点树、班级、题库、试卷、作业考试作答、智能批改、错题本、成绩中心。
- **P1（核心体验，已实现）**：AI 配置、定时任务、附件、随机练习、智能复习、学习笔记、学情/全景报表、教案 CRUD、批改 Agent/规划 Agent/答疑 Agent/路由 Agent。
- **P2（增强，已实现但依赖 LLM 效果）**：题库/试卷/知识点 AI、笔记整理 Agent、教案 AI、收藏/目标/路径/闪卡等学习中心增强。

> 后续演进建议（见架构文档 §11）：Alembic 平滑迁移、schemas 层剥离、令牌吊销外置 Redis、RAG 多租户隔离、前端类型化 API。
