## 1. 总体架构

新芽学堂采用 **单体前后端一体（unified）架构**：一个 Docker 镜像内同时承载 FastAPI 后端（Uvicorn）与构建后的 Vue 前端（Nginx 静态托管 + 反向代理），对外仅暴露 80 端口。后端为异步 ASGI 服务，前端为 SPA，二者通过同源 `/api/v1` 通信，部署无需额外网关。

```
┌──────────────────────────────────────────────────────────────┐
│  Docker 镜像 (unified)                                        │
│  ┌─────────────── Nginx (80) ──────────────┐                 │
│  │  静态资源 /  反向代理 /api/v1 → 127.0.0.1:8000            │
│  └────────────────────────┬────────────────┘                 │
│                           ▼                                  │
│  ┌────────── FastAPI (Uvicorn :8000) ──────────┐             │
│  │  Middleware: GZip / CORS / Audit            │             │
│  │  Router(/api/v1) → Deps(鉴权/权限/DataScope)│             │
│  │  API(v1) → Services → Models(SQLAlchemy)   │             │
│  │  Agents(8) ← LLM / Chroma(RAG)             │             │
│  │  Scheduler(APScheduler, 后台线程长任务)     │             │
│  └──────────┬───────────────────┬────────────┘             │
│             ▼                   ▼                            │
│      SQLite(WAL) 持久化    Chroma 向量库(本地)               │
└──────────────────────────────────────────────────────────────┘
        ▲ 卷挂载 ./data:/app/data（DB + 向量库 + 日志）
```

**关键决策**：
- 单体镜像降低部署门槛（2 核 4G 可跑），适合校内小规模场景；代价是前后端强耦合于同一发版节奏。
- 数据层默认 SQLite（WAL），`core/database.py` 已抽象引擎构建，可平滑切换 PostgreSQL（连接池 `pool_pre_ping`）。
- AI 能力通过 Agent 编排层解耦：有 LLM 走 LangGraph 状态图，无 LLM 降级为顺序规则引擎。

## 2. 技术栈

| 层次 | 选型 |
|------|------|
| 后端框架 | FastAPI + Uvicorn（异步，自动 OpenAPI） |
| ORM / 数据库 | SQLAlchemy 2.0（`DeclarativeBase` + `Mapped`）+ SQLite(WAL)，可切 PostgreSQL |
| 认证鉴权 | PyJWT 双令牌 + PBKDF2-SHA256 密码哈希 + RBAC 三级权限 |

| 定时任务 | APScheduler（BackgroundScheduler，Asia/Shanghai） |
| 日志 | Loguru（文件切割）+ 数据库审计日志 |
| 前端 | Vue 3 + Vite + Element Plus + Pinia + vue-router + ECharts |
| 部署 | Docker 多阶段构建 + Docker Compose + Nginx（一体镜像） |

## 3. 分层设计

系统严格分层，依赖方向单向（上层依赖下层，下层不感知上层）：

| 层 | 目录/模块 | 职责 | 关键文件 |
|----|-----------|------|----------|
| 接入层 | Nginx | 静态托管、反向代理、gzip | `Dockerfile` 内 Nginx 配置 |
| 中间件层 | `middleware/audit.py` | 操作审计、请求上下文 | `AuditMiddleware` |
| 路由层 | `api/v1/*`、`api/router.py`、`api/deps.py` | HTTP 契约、鉴权依赖注入 | 18 个路由模块 |
| 业务层 | `services/*` | 核心业务逻辑、事务边界 | `grading_service`、`auth_service`、`scheduler` |
| 智能层 | `agents/*` | AI 能力编排与降级 | `base.py`、`llm.py`、`rag.py` + 8 Agent |
| 模型层 | `models/*` | ORM 定义、表关系 | `system/edu/question/task/learning/lesson/ops` |
| 数据层 | `core/database.py` + SQLite/Chroma | 连接、迁移、向量存储 | `Base`、`get_collection()` |

> **注意**：项目**无独立 `schemas/` 层**，Pydantic 模型内联在各路由文件中（如 `question.py` 约 1600 行），是后续重构的主要耦合点（见 §11）。

### 4.2 服务层（services）

- **`auth_service.py`**：注册（默认角色+待审批+通知）、审批、认证（异地检测/锁定）、改密/重置、`build_permission_context`（超管 `['*']`，菜单补全）。
- **`grading_service.py`**：教学核心。`save_answers`（先 commit 释放写锁再调 LLM）、`_auto_grade_answers`、`finalize_submission`（重算分/排名/错题/掌握度，仅 `pending_manual=0` 标记 `auto_graded`）、`create_practice_paper/task`、`grade_summary`。
- **`ai_config_service.py`**：`get_ai_config`（脱敏+上限收敛）、`save_ai_config`（校验+触发 LLM 客户端重载清熔断）、`test_ai_connection`（从 sys_config 取真实 key）。
- **`scheduler.py`**：APScheduler 封装，`sync_all_jobs`/`add_job`/`run_job_now`/`scheduler_status`。
- **`task_jobs.py`**：7 类定时任务（`clean_expired_exams`/`generate_daily_report`/`weekly_report`/`clean_temp_attachments`/`push_review_reminders`/`clean_old_logs`/`publish_scheduled_tasks`），`JOB_HANDLERS` 注册表。
- **`init_db.py`**：种子数据（权限点/角色/年级学科/知识点树/默认管理员/演示数据），权限点幂等对齐。
- **`attachment_parser.py`**：Excel 批量导入题目/知识点。

### 4.4 核心层（core）

- `config.py`：`Settings(BaseSettings)`，唯一真源 `VERSION` 文件、`APP_NAME="新芽学堂"`、`API_PREFIX`、DB 路径、`SECRET_KEY` 解析（生产弱密钥 fail-closed）、LLM/Chroma/RAG/复习间隔/4 个 cron 配置。
- `database.py`：`Base` + `_build_engine`（SQLite `check_same_thread=False`、`timeout=10`；connect `PRAGMA journal_mode=WAL; busy_timeout=5000; foreign_keys=ON; synchronous=NORMAL`）。
- `security.py`：PBKDF2 哈希、`create/decode_token`（含 jti，`db` 非空时查 `sys_revoked_token`）、验证码、弱口令黑名单。安全 TTL 缓存（验证码/吊销名单/找回码）落库共享，见 `models/security_cache.py`。
- `exception.py`：`AppException`/`NotFoundException(404)`/`PermissionException(403)`/`AuthException(401)`/`BusinessException(400)`，统一返回 `{code,message,success}`。
- `rate_limit.py`：`check_agent_rate` 按用户+分钟窗口限流，fail-open。
- `db_migrations.py`：`run_column_migrations`/`run_knowledge_v2_migration`/`run_question_v2_migration`（贴源迁移，非 Alembic）。

### 4.5 智能层（agents，8 个）

注册于 `agents/base.py:load_agents()`，统一契约 `BaseAgent` + `AgentResult`；编排层 `Orchestrator` 优先 LangGraph，否则顺序降级。

| Agent | name | 作用 | 调用入口 |
|-------|------|------|----------|
| RouterAgent | `router` | 意图路由分发 | `/chat`、`/chat/stream` 自动路由 |
| QuestionGeneratorAgent | `question_generator` | RAG+LLM 生成题目 → `status="draft"` 待审 | `/question-generator`、组卷补题 |
| PaperComposerAgent | `paper_composer` | 自然语言→规则组卷，缺题回调 #2 | `/paper-composer` |
| GradingAgent | `grading_assistant` | 客观题本地判分，主观题 LLM 并发（≤8 线程） | `/grading` |
| StudyPlannerAgent | `study_planner` | 学情→复习计划，落 `ReviewPlan` | `/study-planner` |
| TutorAgent | `tutor` | RAG+笔记上下文讲解，fallback SQL | `/tutor` |
| NoteOrganizerAgent | `note_organizer` | 大纲/思维导图，写回 `Note.ai_*` | `/note-organizer` |
| LessonPlanAgent | `lesson_planner` | 两段式生成（head/body 防 token 截断），规则兜底 | `/lesson/ai/generate` |

底座：`llm.py`（`LLMClient` OpenAI 兼容，永久熔断+指数退避冷却，`log_agent_call` 用 daemon 线程落库避免 SQLite 写锁争用）；`rag.py`（Chroma 懒加载、后台预热、混合检索、`student_id` 归属过滤防越权）。

- **入口/布局**：`main.js`（全局 errorHandler，`isBusinessError` 跳过已提示错误）→ `App.vue` → `layout/MainLayout.vue`（按路由前缀分组菜单，AI 组须在系统管理前）。

## 6. 鉴权与权限模型

- **依赖注入**（`api/deps.py`）：`get_current_user`（Bearer 解析、过期判定、首登改密白名单拦截）→ 角色依赖 `get_current_admin`/`get_current_manager`/`get_current_teacher`/`get_current_student`/`get_current_student_self`。
- **数据范围** `DataScope`：非超管返回**显式列表**（grade_ids/class_ids/student_ids）而非 None，严格隔离防越权；作答类接口双重校验 `student_id + class_id` 下发关系。
- **权限点**：约 60 个（menu/button 两类），如 `system:user:list`、`question:bank:write`、`grading:do`、`agent:chat`；`init_permissions()` 幂等对齐 path/icon，避免"代码改、库未同步"孤儿菜单。
- **令牌吊销**：落 `sys_revoked_token` 表（`jti` 主键 + `expire_at` 索引），跨进程/多 worker 共享。读路径自带 TTL 语义（`expire_at >= now_local()`），清理退化为纯优化。**注意**：`decode_token` 必须传 `db`，漏传即跳过吊销检查（`api/deps.py:56`、`auth.refresh_token`、`auth.logout` 均已传）。

## 7. 关键数据流

### 7.1 出题→组卷→布置→作答→批改→学情（主链路）

```
teacher: POST /question/questions (或 /question-generator)
   → Question(status=draft) → 审核入库
teacher: POST /question/papers (或 /paper-composer)
   → Paper + PaperItem
teacher: POST /task/tasks (type, publish_at?)
   → Task + TaskAssignment（或 student_ids 跨班）
student: GET /task/tasks/{id}/paper   （不含答案）
student: POST /task/tasks/{id}/submit (content + answers[paper_item_id])
   → grading_service.save_answers
       1) commit 释放写锁
       2) _auto_grade_answers（客观题本地判分）
       3) GradingAgent（主观题 LLM 并发批改，pending_manual 计数）
       4) finalize_submission: 算分/排名/_collect_wrong_question/_update_mastery/_record_study
teacher: GET /grading/pending → POST /grading/submissions/{id}/grade（采纳/修正）
   → POST /grading/submissions/{id}/publish
student: GET /task/my/scores + /learning/wrong-questions + /learning/review/plans
```

### 7.2 AI 长任务异步链路

```
前端 POST /lesson/ai/generate（或 /agent/jobs）
   → 后台线程 _run_job 执行 AgentJob（状态机：running→success/failed）
   → 前端轮询 GET /jobs/{id}（教案 2s，resumeJobId 断点恢复）
   → 完成返回结构化结果 → 用户预览 → POST /jobs/{id}/save 落库
```
> 生成与保存分离；`_assemble()` 结构兜底（缺章节补模板、环节补足到 5 个、时长缩放），`generation.quality` 标注 low/medium/high。

### 7.3 RAG 检索链路

```
POST /edu/knowledge/search（或 /agent/tutor）
   → rag.search(): Chroma 向量优先 → 命中不足 SQL LIKE 降级
   → student_id 过滤笔记归属防越权 → 返回片段 + 引用来源
```
> 首次检索触发 `start_chroma_warmup()` 后台预热（约 79MB 模型下载），否则首请求极慢/超时。

## 8. 部署与运行

- **多阶段 Dockerfile**：backend-builder（编译依赖）→ backend-base（Noto CJK 字体）→ frontend-builder（`npm ci`）→ backend → unified（Nginx 一体，烧录 `BUILD_INFO`/`GIT_COMMIT`）。
- **docker-compose.yml**：`app` 服务 build target `unified`，`ports 8080:80`，必填 `SECRET_KEY`，`volumes ./data:/app/data`（DB/向量/日志持久化），`healthcheck` 探 `/api/v1/health`。
- **四层一致性（最高纪律）**：本地代码 / `origin/master` / GHCR 多架构镜像（`ghcr.io/chenhui-001/edu-ai-platform`）/ 服务器容器，必须同源同一 commit。`tools/verify_consistency.py` 校验四层指纹 + 镜像 sha256。
- **发布流程**：本地源码回归（`auto_ship.sh` 复用 `run_e2e.sh`）→ commit/push GitHub → CI + GHCR 多架构构建 → 本地/服务器拉取同一镜像并校验。`VERSION` 文件为版本唯一真源，改动代码路径须 `--bump`。
- **已知约束**：Alembic 已入依赖但未初始化，表结构变更靠 `create_all` + `db_migrations` 贴源迁移，无法平滑迁移历史库。

## 9. 设计模式与已知约束

**设计模式**：单例（Orchestrator/LLM 客户端/Chroma collection 懒加载）、依赖注入（`Depends` 鉴权/权限/DataScope）、策略/降级（RAG→SQL、Agent→规则引擎、LLM→fallback）、异步长任务（AgentJob+后台线程+轮询）、统一响应/异常（`ok()` + `register_exception_handlers`）。

**已知约束（改代码/排障前必读）**：
1. `/health` 返回服务端 naive 本地时间（`server_time`），跨时区部署需警惕。
2. Chroma 首请求预热下载约 79MB 模型，须后台预热。
3. 令牌吊销名单进程内，多副本需换 Redis。
4. SQLite 写锁：`save_answers` 先 commit 再调 LLM；`log_agent_call` 用 daemon 线程落库避免死锁。
5. 路由注册顺序敏感：`/practice/history` 须早于 `/practice/{task_id}`，否则 422。
6. `/learning` 经 `grading.learning_router` 兼容挂载，真实实现在 `api/v1/learning/`，易误寻。
7. 无独立 `schemas/` 层，Pydantic 内联路由，随文件膨胀耦合度高。
8. 默认口令处置：`init_admin` 建新管理员即置 `must_change_password=True`；存量库由 `enforce_default_admin_password`（`init_db.py`）按**权限归属**找出所有仍在用 `Admin@123456` 的超管并强制改密。生产（`DEBUG=false`）额外写 `sys_error_log`。
9. 限流 fail-open（异常放行），不做硬拒绝。

## 10. 功能逐项分析（作用 / 实现逻辑 / 潜在改进点）

> 按业务域逐条拆解，便于评审与迭代排期。

### 10.1 系统基础

**注册审批**
- 作用：师生自助注册，管理员审核后激活。
- 实现：`auth.register_user` 建 `Registration`+通知；`system.registrations/audit` 审批；`auth_service.audit_registration`。
- 改进：支持邮件/短信通知；审批流可配置（自动通过/分级审批）；注册信息字段校验增强（真实姓名/年级绑定）。

**登录/刷新/登出**
- 作用：JWT 双令牌认证，登出吊销。
- 实现：`security.create_access/refresh_token`（jti）；`decode_token(token, db)` 查 `sys_revoked_token`；`/auth/logout` 写吊销（幂等，先删同 jti 再插）。
- 改进：refresh 轮换（refresh token 一次性）防重放；异地登录二次验证。

**验证码**
- 作用：防暴力破解。
- 实现：`security.generate_captcha` 出图 + `store_captcha(text, db)` 落 `sys_captcha`（一次性，校验即删）+ `verify_captcha(db, key, text)`。取码按 IP 限流 30 次/分钟（`auth._check_captcha_rate`，进程内桶）。
- 改进：滑动/行为验证码；**登录接口目前是「传了 captcha_key 才校验」，不传直接放行**（`auth.py:189-192`），这是待修的口子（S7），强制化需同步改前端 `Login.vue` 的取码失败降级。

**RBAC 三级权限**
- 作用：菜单/操作/数据三级授权。
- 实现：`init_db.PERMISSIONS`（约 60 点）+ `ROLES`；`deps.has_perm`/`require_perm`；`init_permissions` 幂等对齐。
- 改进：权限点回归测试覆盖（防契约漂移）；前端菜单与后端 `Depends` 自动对账脚本；细粒度数据范围表达式。

**三类日志 + 审计**
- 作用：操作可追溯、安全审计。

- 改进：日志脱敏（密码/密钥不落库）；审计日志独立存储与归档策略；导出为 SIEM 友好格式。

**定时任务**

## 11. 演进建议（优先级排序）

1. **拆分 schemas 层**：将内联 Pydantic 模型外置，降低 `question.py`/`knowledge.py`/`agent.py` 耦合，提升可测性（P1）。
2. **平滑迁移**：以 Alembic 替代 `create_all`+贴源迁移，支持历史库无损升级（P0，否则版本迭代风险高）。
3. **多 worker 水平扩展**：验证码/吊销名单/找回码已落库（前置条件已解决），剩余阻塞为 `init_all` 启动锁、APScheduler 每进程各跑一遍、SQLite 单写者竞争 —— 见「已知限制」。
4. **RAG 租户隔离**：知识点/笔记检索按年级/班级隔离，强化数据合规（P1）。
5. **前端类型化 API**：引入 TS 接口契约或 OpenAPI 代码生成，消除前后端契约漂移（P1，对应"契约漂移"历史坑）。
6. **异步任务队列化**：以持久化队列（如 Redis/RQ）替代后台线程 `_run_job`，支持取消/重试/可观测（P2）。
7. **对象存储外置**：附件/向量库/日志考虑外置，降低单机卷压力（P2）。
8. **可观测增强**：Agent 调用成本/质量面板、定时任务失败告警、日志脱敏审计（P2）。
