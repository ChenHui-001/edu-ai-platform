## 4. 验证方法与执行结果

### 4.1 验证方式

### 4.3 全量执行说明（诚实披露）
本次**未对 156 条用例逐条做写操作级 E2E**（如真实创建题目→组卷→发布→学生作答→批改全链路），原因：
- 写操作类用例（POST/PUT/DELETE）多依赖前置数据（如先有年级/学科/知识点才能建题）与 LLM（AI 出题/组卷/教案/批改需联网或走规则引擎降级）；
- 全链路已在既有 `tools/run_e2e.sh`（15 阶段）与 `backend/qa_audit_suite.py`（30 passed）中覆盖核心路径。
本套 `functional_*` 为**可持续回归的独立用例集**，执行器 `functional_runner.py` 已就绪，CI 接入后可在每次发版跑全量（含写操作，需预置种子数据）。

## 5. 规范化用例集（可用于自动化测试）

**单一来源**：`functional_cases.py` → 生成 `FUNCTIONAL_TEST_CASES.json` + `FUNCTIONAL_TEST_CASES.csv`。

**字段（每条用例）：**
`id, role, module, menu, element, action, priority, precondition, steps, expected, api, automation{type,method,path,body,assert,locator}`

- `automation.type=api` 的用例可直接由 `functional_runner.py` 驱动（method/path/body/assert 完整）；
- `automation.type=ui` 的用例提供 `locator`（如 `text=新增用户`、`.el-tree`），可由 Playwright 绑定；
- `automation.type=manual` 为需人工/特殊数据的用例（如 LLM 可用态）。

**运行方式：**
```bash
# 生成用例
python functional_cases.py --emit
# 查看覆盖矩阵
python functional_cases.py --coverage
# 连本地/CI 后端执行接口级冒烟
BASE_URL=http://127.0.0.1:8899/api/v1 \
QA_ADMIN="admin|Admin@12345678" QA_TEACHER="teacher1|Teacher@123" QA_STUDENT="stu101|Student@123" \
python functional_cases.py --run
```
> 注：种子 admin 默认 `must_change_password=true`，首次登录后需先改密（如 `Admin@123456`→`Admin@12345678`）方可访问受保护接口——这是产品强制改密机制，非缺陷。

## 6. 风险与待办（需在回归中持续盯防）

| 风险点 | 关联用例 | 说明 / 缓解 |
|---|---|---|
| LLM 不可用降级 | AI 出题组卷/教案/批改/智能助手 全部 | 未配 Key 时走规则引擎，功能不中断；用例均标注"降级分支需覆盖" |
| 导出鉴权 | 系统报表/教学报表/错题本/知识点 导出 | blob 下载必须带 `Authorization`（不能 `window.open` 直开），否则 401 |
| 强制改密拦截 | 公共·登录/个人中心 | 出厂口令登录后全接口 403 直至改密；自动化需预置已改密账号 |
| 跨年级学科 id 还原 | 学生端全部筛选/练习/组卷 | 下拉用 distinct 代表 id，提交需 `resolveSubjectId` 还原本年级精确 id，否则查空 |
| 知识点数据缺口 | 知识点管理/AI 出题 | 59 学科约 42 个无知识点，AI 出题挂不上、掌握度失效（数据问题，非代码） |
| 批量操作仅本人 | 题库/试卷/教案 批量 | 混合勾选他人记录整体拒绝，需权限边界用例 |
| 组卷难度/分值校验 | 新建试卷向导 | 难度合计=100% 且卷面分=总分才可生成，否则按钮置灰 |
| XSS 净化 | 学习笔记/题干/AI 回复 | `v-html` 前经 `sanitizeHtml`，需注入用例验证 |

## 7. 结论

- **覆盖**：48 个菜单、156 条用例，管理员/教师/学生三角色所有按钮与输入框均已枚举并落表，**零遗漏**。
- **门禁**：P0 用例所在菜单的可达性与越权保护经真实后端验证（20/20 冒烟通过）；跨角色越权正确返回 403；版本信息新功能与系统配置契约修复均验证通过。
- **可执行性**：用例集已规范化（JSON/CSV + 执行器），可纳入 CI 做发版回归；写操作级全链路建议与既有 `run_e2e.sh` 互补运行。
- **判定**：当前基线 **达到发版门禁（功能可达性 + 权限隔离绿灯）**；AI/导出/降级等增强项需在 LLM 可用环境与预置数据下补跑写操作用例。
